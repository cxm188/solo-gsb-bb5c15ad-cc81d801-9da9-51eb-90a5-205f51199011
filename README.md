# 视频接片单核对工具（EDL Checker）

粘贴接片单 CSV，自动核对时间码合法性、素材/成片帧时长，以及成片时间轴上的**全部空隙与重叠区间**。

- 前端：React 18 + TypeScript + Vite
- 后端：Node.js + Express（核对逻辑在服务端）
- 部署：单镜像 Dockerfile + docker compose（依赖安装与前端构建均在镜像构建时完成）

## 一条命令启动

```bash
docker compose up --build -d
```

启动后打开：

**http://localhost:3000**

停止：

```bash
docker compose down
```

> 首次启动会自动安装前后端依赖并构建前端，全部发生在镜像构建阶段，无需手动 `npm install`。

## 必要配置（均为可选项，有默认值）

| 配置 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 宿主机端口 | compose 变量 `HOST_PORT` | `3000` | 例：`HOST_PORT=8080 docker compose up --build -d`，然后访问 http://localhost:8080 |
| 容器内监听端口 | compose `environment.PORT` | `3000` | 一般无需修改；若改动需同步调整端口映射 |

帧率模式**不是**配置文件项，而是在网页右上角统一选择，对整份接片单生效：

- **25 fps 非丢帧（PAL）**：帧号 `00–24`，每帧连续计数；
- **29.97 fps 丢帧（NTSC DF）**：标称 30 fps，帧号 `00–29`；每个非整十分钟
  （第 1–9、11–19… 分钟，跨小时同理）**开头**的帧号 `00`、`01` 不存在，该分钟从 `MM:00:02`
  开始，共 1798 帧；**整十分钟**（第 0、10、20… 分钟）不跳，共 1800 帧；每小时 107892 帧。

> 注意：丢帧只跳过丢帧分钟**开头**的两个帧号；该分钟内其他秒（如 `MM:01:00`）的帧号 00、01 仍合法。

## 输入格式

CSV 每行 5 列，支持带表头（按列名识别）或无表头（按固定顺序）：

```csv
片段名,素材入点,素材出点,成片入点,成片出点
sc01,00:00:10:00,00:01:40:00,00:00:00:00,00:01:30:00
```

- 时间码格式固定为 `HH:MM:SS:FF`，小时范围 `00–23`。
- 区间为**半开区间 `[入点, 出点)`**：入点包含、出点不包含；因此出点必须严格晚于入点。
- 以下情况会被拒绝并在对应行报错：
  - 帧号超出范围（25fps 出现 25–29；29.97DF 出现 29）；
  - 丢帧模式下非整十分钟开头出现帧号 `00` 或 `01`（如 `00:01:00:00`、`00:01:00:01`）；
  - 出点早于/等于入点（含跨午夜区间，本工具不支持跨午夜）；
  - 列数不是 5 列、字段为空、时间码格式错误。
- 时长核对：先把入/出点换算为**实际帧数**，要求 `素材出点-素材入点 == 成片出点-成片入点`，
  丢帧模式下的换算自动扣除每分钟跳过的 2 帧。

## 核对结果

- **问题清单**
  - 非法行 / 时长不一致（给出帧数差与时间码）；
  - **重叠区间**：采用扫描线对同一时刻活动区间做**全量两两配对**，不只是相邻行——
    因此非相邻行的重叠、一个区间完全包含另一个区间都会被列出，每对给出相关原始行号、重叠起止与帧数；
  - **空隙区间**：成片区间合并取并集后，列出所有未覆盖段及其前后相邻片段的行号；
  - 首尾相接（上一段出点 = 下一段入点）按半开区间语义视为正常，不报空隙也不报重叠。
- **成片时间轴**：覆盖 / 空隙 / 重叠可视化，点重叠块可定位。
- **排序后的成片区间**：按成片入点排序，标注原始行号与顺序号。
- 点击任何「第 N 行」按钮（或行号槽），左侧编辑器高亮并滚动到原始行；底部详情面板同时显示
  各入/出点的**时间码与绝对帧数**、两侧时长帧数。
- 网页上点「**载入示例接片单**」可获取包含空隙、重叠（含非相邻包含）、时长不一致、非法帧号、
  跨午夜等问题的示例数据，两种帧率各一份。

## 本地开发（不用 Docker）

需要 Node.js ≥ 20。

```bash
# 终端 1：后端（http://localhost:3000）
cd server
npm install
npm run dev

# 终端 2：前端（http://localhost:5173，/api 已代理到 3000）
cd client
npm install
npm run dev
```

打开 http://localhost:5173 开发调试；生产构建由 `npm run build` 生成 `client/dist/`，
由 Express 一并托管。

## 健康检查

`GET /api/health` 返回 `{"ok":true}`，已在 Dockerfile 与 compose 中配置 HEALTHCHECK。
